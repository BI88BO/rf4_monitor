# 浮窗搏鱼状态行（体力% + 出线米）设计

日期：2026-08-16

## 背景与目标

RF4 Monitor 已确认搏鱼拉力消息(14/8)中：
- 扫描浮点组第 2 组首位 = **鱼体力**（1.0=100%，转百分比 `(v-0.1)/0.9*100`，越界钳制）。实测 553 帧仅 2 帧为 0，字段稳定。
- 第 4 组 `(0,0,1,X)` 的 X = **出线距离（米）**。

当前搏鱼输出问题：
1. **行太长/字段多**：搏鱼拉力行带浮点2/3/4/5 全组、拉力方向、负载、序号
2. **出线距离瞬时抖动**：搏鱼开始阶段会闪现负值（实测 -10.7、-0.04）或大跳变
3. **进入搏鱼阶段帧无体力字段**：只有状态值(距离类)，需在进入时合成初始体力

目标：拉鱼时浮窗显示**精简的搏鱼状态行**（体力% + 出线米），仿 RF4-Tools 作者的 HUD。

## 需求（已确认）

- 精简搏鱼行：去掉浮点组/拉力方向/负载/序号
- 单行紧凑：`3号杆 | 体力 78% 出线 12.3米`
- **进入搏鱼阶段(14/11)即显示**，该行带鱼名/重量；之后搏鱼拉力(14/8)刷新体力/出线，结束消失
- **过滤异常帧**：出线负值/瞬时跳变帧不显示
- 体力 ≤ 0 时行变红

## 设计

### 1. bridge.py：精简 `_format_fight_load_payload`

`rf4_core/bridge.py:2379` 当前输出：钓组、鱼编号、鱼名、重量、拉力方向、负载、浮点2/3/4/5全组、出线、序号。

改为只输出：
- `钓组=短ID`
- `鱼=名称 重量=X`
- `体力=X% 出线=Y米`

移除：拉力方向、负载、浮点组、序号。

### 2. bridge.py：异常帧过滤

出线距离 `_fight_distance` 结果过滤：仅当 `0 < X <= 40` 才采用（实测上限 40 米）；负值/超限/跳变帧跳过，保持上一帧值。体力字段沿用现有 `0.05 <= v <= 1.05` 校验。

### 3. bridge.py：进入搏鱼阶段(14/11)输出初始体力行

`_handle_client_frame` 的 fight_stage 分支（`rf4_core/bridge.py:2848`）当前触发 BITTEN 事件。追加构造精简初始行：
- 鱼信息：鱼名 + 重量（复用该分支已有的 `meta = session.fish_setup_cache[...]`，保证进入搏鱼即显示鱼的信息）
- 体力 = 100%（进入即满，首条拉力帧 1~2 秒后更新真实值）
- 出线 = 进入帧状态值[0]（实测约 27~37 米，量级正确；首条拉力帧会修正偏差）

作为 fish 遥测输出，走 `_broadcast_telemetry(category="fish")`。

### 4. rf4_overlay.pyw：搏鱼行就地刷新

- `telemetry` 事件（category=fish）每 2 秒一条精简行
- 在 text 中带竿号前缀（`3号杆 | ...`），浮窗按前缀识别并**就地更新**该竿行，不追加滚动
- 体力 ≤ 0 → 行文字变红
- 收到 `fish_kept`/`fish_escaped`/`fish_released`（同竿号）→ 清除该行（现有 clear_after 机制）

### 5. 开关与默认

- 不新增配置项。跟随现有 `rf4_show_fish`（"遥测·钓鱼过程"）勾选。

## 测试

- bridge 测试：fight_load 帧 → 精简行不含浮点组/拉力方向，含 体力/出线
- bridge 测试：出线负值/超限帧被过滤，保持上一帧值
- bridge 测试：fight_stage 帧 → 输出初始体力行（100%），含鱼名/重量
- overlay 测试：投递含竿号的 telemetry 行 → 按竿号就地更新而非追加
- 回归：现有 42 个测试保持通过

## 风险

- 体力字段（groups[1][0]）是推断，已验证 67 条鱼 553 帧，仅 2 帧异常为 0
- 初始出线（进入帧状态值[0]）与首条拉力帧有 0~8 米偏差，由首条拉力帧 1~2 秒内修正
- 浮窗按文本前缀识别竿号，需与 bridge 输出格式保持一致（`{竿号} | ` 前缀约定）
